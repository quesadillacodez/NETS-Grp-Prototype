# NETS application server

The Vite app and `/api` routes run from one Node process locally. On Vercel,
`api/index.mjs` exposes the same request handler as a Node Function while
Vercel rewrites `/api/*` to it and serves the Vite bundle. The server owns PIN hashes, sessions, login
throttling, recovery challenges and the synchronized SQLite snapshot. Browser
code never receives PIN hashes or session tokens.

## Required production configuration

- `NODE_ENV=production`
- `SESSION_SECRET`: at least 32 random bytes, kept outside source control
- `KV_REST_API_URL` and `KV_REST_API_TOKEN`: generated by the Vercel Redis
  integration. `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` are also
  accepted.
- `NETS_REDIS_STORE_KEY`: optional key namespace for the prototype store
- `OTP_WEBHOOK_URL`: HTTPS endpoint that accepts the JSON SMS request
- `OTP_WEBHOOK_TOKEN`: optional bearer token for that endpoint
- `NETS_SEED_USERS_JSON`: optional replacement for the documented demo users

For local development, omit the Redis variables and the server falls back to
the ignored `NETS_DATA_FILE`. A real banking rollout should replace this
single-record prototype store with an audited transactional database, a
distributed rate limiter and an approved identity/OTP provider.
